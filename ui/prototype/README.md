# 画面試作

[index.html](index.html)をブラウザーで開く。CSSとJavaScriptは同じディレクトリから読み込み、外部CDN・フォント・APIを使用しない。リポジトリ取得後のファイルを直接開くか、ローカルの静的ファイルサーバーで表示できる。

例：リポジトリrootで `python -m http.server 18741 --bind 127.0.0.1` を起動し、`http://127.0.0.1:18741/ui/prototype/` を開く。静的ファイルの表示だけで、モデル接続やベンチマークは開始しない。

## 操作できる範囲

- 比較結果・比較作成・ケース明細の画面切替。
- 架空のモデル2件とエンジン設定の選択。
- 生成プリセットの選択・複製・温度等の編集・基準との差分確認。
- Quick / Detailedのケース集合と独立した試行回数（既定1）、1 / 3 / 5回の入力補助と自由入力。
- セット・モデル切替やpreset複製で回数を保持し、構成×ケース×回数を計算。
- 基底seed、全試行集計の方針、読みやすい計画確認と折りたたんだJSON。
- 架空のケースの絞り込み、最終回答・操作履歴・採点根拠の切替。
- 架空の結果例を非表示にし、未測定の状態を確認。

値はブラウザー内のメモリだけで保持する。実測結果の取得、endpointへの接続、設定の保存、モデル起動、評価の実行は未接続。

## 表示データ

モデル名・問題・回答・採点・速度・消費はすべて架空。元の公開ベンチマークや実モデルの成績ではない。正誤式と最適化の単位、思考・cacheの包含、対象モデルとhelperの区別がわかる表示例にしている。

## 検証

Node.jsが利用できる場合は、追加パッケージなしで状態計算の検査を実行できる。

```sh
node --check ui/prototype/app.js
node ui/prototype/test-state.cjs
```

画面では、モデルを外したときの試行数、複数preset、無効な数値、dialogの閉じ方、回答と根拠の表示、狭い画面での読みやすさを確認する。正式UIの受入は[画面設計](../../docs/10-interface-and-configuration.md)に従う。

画面の改善点と確認範囲は[画面レビュー](../../docs/11-ui-review.md)に記録する。
