## ユーザーと合意した方針

| ID | 方針 | 根拠 |
|---|---|---|
| D01 | StackPiles所有の公開リポジトリとして作る | 作成先と公開範囲の明示指定 |
| D02 | 通常能力を共通frameworkで比較する | ローカルLLMを同じ問題・条件で測る目的 |
| D03 | Quick / Detailedの二つを用意する | 短い選別と、広い範囲・反復による確認を分ける |
| D04 | 独自の累積出力・操作回数制限を追加しない | 当初の予算制限案からの明示修正 |
| D05 | 品質に加えてトークン消費量と速度を測る | 追加指定 |
| D06 | 営業を対象能力の候補に含める | 将来の営業タスクも評価対象とする |
| D07 | 選定問題の日本語版を初版から準備する | 日本語へ対応できるものを最初から対応する方針 |
| D08 | 原文・翻訳・検証記録を保存し、公式日本語と独自翻訳を区別する | 日本語化に伴う問題・測定器の変更を追えるようにする |
| D09 | 原回答と採点を保全し、同一条件で再利用・再採点する | 既存評価からの継続要件 |
| D10 | 中継ホストは中継・保存・監視を担う | 計算と重い採点を中継へ置かない既存運用方針 |
| D11 | 特定の非公開プロジェクト名や個別業務を識別する情報を公開しない | 公開範囲の明示修正 |
| D12 | モデル・設定を簡単に切り替えて、さまざまな条件を試せるようにする | 追加指定 |
| D13 | 進捗と比較結果を、見やすい画面で確認できるようにする | 追加指定 |

## 初版の設計案

| ID | 案 | 固定前に必要な確認 |
|---|---|---|
| P01 | Quick 20×1、Detailed 100×3、QuickをDetailedへ含める | 実際の問題IDと所要時間・較正・実行性 |
| P02 | 共通API接続とbenchmark別adapter | nativeハーネスを変えずに全呼び出しを捕捉できるか |
| P03 | 日本語を主評価、英語は別のQA対照 | pack・helper変更の有無と集計単位 |
| P04 | 温度1.0 / top-p 0.95 / 256K・一要求128Kの参照profile | backendの有効設定と容量対応。互換14問は元の全条件を保存 |
| P05 | 対象case間cold、同じ対話内のcache再利用を許す | 対応backendでの制御と実測counter |
| P06 | 独自の総合点を初版では作らず分野別に表示 | 将来集約する場合の変換と重みの事前定義 |
| P07 | モデル・エンジン・生成プリセットを分離し、UIとCLIで同じresolverを使う | パラメーターの対応、設定schema、fake endpointの検証 |
| P08 | ローカル画面で比較作成・進捗・結果・ケース明細を扱う | UI試作を使った操作確認と、実データ接続後の受入 |
