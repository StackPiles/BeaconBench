# 07 実行環境・分離・復帰

## 役割

| 役割 | 置くもの |
|---|---|
| controller / relay | 計画、軽い状態確認、ログ中継、保存。推論・重い採点は行わない |
| target compute | 評価対象モデルと推論エンジン |
| support compute | 対話中の顧客役・変換役・必要な補助モデル |
| evaluation executor | 生成コード・公式checker・CRM模擬環境・事後採点 |

一台のDGX Sparkに複数の役割を置く場合も、時間帯・メモリ・GPU競合を管理する。中継ホストのメモリへ全回答・モデル・採点データを展開しない。SWE-bench Pro V2等のamd64資産は専用のx86 Linux executorを候補にし、ARM64で動作確認していないものを実行可能と表示しない。

## 単発生成と対話の実行

単発コード生成は、対象構成の全生成を保存してからモデルを解放し、同じ計算ホストで採点する構成を支持する。原回答とgeneration完了markerを照合してからgraderへ渡す。

BabelArenaやSalesLLMでは顧客の次の発言が必要なので、すべての補助処理を全生成後へ回すことはできない。固定したsupport endpointを実行中に使う。補助モデルを同じGPUで常駐させる場合は、対象モデルの速度・空きメモリに影響する実行構成として記録する。軽量化のために顧客役を無検証で小型化しない。

有料APIをsupport endpointとして使用することは設定可能な設計とし、既定で外部の有料APIを呼ばない。planにroleと呼び出し先・計測範囲を出す。具体的な顧客・judgeモデルは未選定。

## 資源の所有

runは計算ホストごとのleaseを取得する。開始前に対象サービスの同一性、実行中要求、メモリ、他runの所有を確認する。負荷が不明な既存サービスを停止しない。

専用endpointへ接続する実行を基本とする。常用サービスを一時停止する運用はoperatorが設定したhost lifecycle adapterに限定し、事前の状態と復帰先を保存する。過去のrunが持つ古いcontainer IDを常用サービスの現在IDとして使わない。

推論・コード採点・GPU judgeを同時に走らせて速度を測らない。並列度はprotocolで固定し、外部負荷がある場合は証拠と `measurement_contaminated` を残す。

## 生成コードと模擬業務

コード実行は固定イメージの隔離環境で行う。モデル重み、ホストcredential、常用サービスの管理ソケットを渡さない。公式が必要とするCPU・メモリ・実行時間とnetwork policyを記録し、全構成で揃える。

採点用の隠しテスト・参照解をagentの作業環境へ混ぜない。agentが編集したファイルをそのまま採点器の実装として使わない。SWE-bench Pro V2は取得したpatchを清浄な環境へ適用して再採点する公式方式を維持する。

CRM・メール・予定表等のtoolは、ベンチマーク用の模擬サービスまたは配布元が指定する評価環境へ接続する。通常業務のアカウントへ置き換えて起動しない。初期状態のsnapshotとresetを毎試行で確認する。

## 認証とアクセス

モデルのAPIキーは環境変数名で指定し、run manifestには値を出さない。HTTP header、query string、tool応答のcredential候補をログ保存前に分離する。非公開の原本が必要な場合は公開レポート用の許可項目とは保存先を分ける。

benchmark processは対象endpointの公開推論APIを使い、常用の開発用RPCを前提にしない。管理操作が必要ならhost lifecycle adapterに権限を限定する。常用APIの認証やnetwork policyを評価のために弱めない。

## 中断と復帰

例外・利用者停止・採点失敗でも、所有するプロセスとleaseだけを処理する。原回答と未完了streamを保存し、再開時に完成した回答を再利用する。

常用環境を変更したrunは、保存した設定に戻し、実際の推論応答・モデルID・サービス同一性を確認する。復帰に失敗した場合はrunの成績と独立して警告状態を残す。単にprocessが起動したことを復帰成功としない。

このリポジトリの設計資料・静的検査は、計算ホストの状態変更、モデルダウンロード、常用サービスの停止、定期スケジュール登録を行わない。
