# 一部の課題だけを再測定する

指定した課題だけを新しく生成・採点し、他の保存済み回答と採点をそのまま使って全体を表示する。再測定するケースの追加・条件変更は、常に明示的な実行指示から行う。

## 記録の構成

実際の計測用runには指定ケースだけを含める。統合用runは保存結果を参照する読み取り専用の表示であり、生成workerを起動できない。元回答の生成識別値・原本の参照先・当時の実行基盤を保持する。現在の識別値に書き換えて自動キャッシュ照合を通す方法は使わない。

統合結果は、残したケースを最初から生成・採点済みとして表示する。新しい課題が完了すると、その実回答と採点を参照して更新する。回答全体の消費量には再利用分を含め、この再測定で観測した消費は計測用runの要求だけを集計する。

## 再利用の確認

- 元runが完了していること、同じケースID集合・試行回数・seed方針であること。
- 残す回答の商品情報・問題・環境資産・生成条件、モデル・実要求、実際に生成へ使う補助役とnative実行器が一致すること。
- 完了回答の原本SHA、採点原本SHA、採点条件・採点環境が一致すること。採点器の受入証拠を追加しただけの更新は実装の変更と区別する。
- 採点条件を更新した課題を残す場合は、今回のpackと一致する保存回答点検版があること。単に新しい日付という理由で別条件の採点を採用しない。

実行基盤の版が異なることを明示し、生成入力・環境・測定器を比較する。保存観測を別版の全体表示へ持ち込む操作であり、現在の基盤ですべてを新規測定したとは表示しない。条件が違うケースを黙って再生成・再採点せず、準備を停止する。

## 明示実行

```sh
uv run beaconbench subset-prepare local/subset.json
uv run beaconbench subset-worker COMPOSED_RUN_ID
```

設定には `source_run_id`、`suite_id`、`regenerate_case_ids` と、必要なら `evaluation_revision`、表示する `name` を指定する。単一構成の完了済みrunを対象とし、再測定は空でない一部のケースに限る。生成プリセットと反復は元のrunから引き継ぐ。

`subset-prepare` は条件照合と保存結果の準備だけを行い、モデルを呼ばない。`subset-worker` は計測用runを1件起動して更新を監視する有限の処理。計測・採点の完了または停止・失敗で終了し、他のケースやモデルへ続けない。統合画面の停止要求は計測用runへ伝える。

Windowsから独立して継続する運用では、管理ホスト上の独立プロセスとしてこの有限の処理を起動する。定期タスクや新しい推論サービスを追加する必要はない。原本や固定runtimeの更新は行わない。中断時は計測用runを確認して復旧し、読み取り専用の統合結果を通常の生成workerで再開しない。

## 検証範囲

架空の2ケースを使い、1ケースの生成・採点だけが増えること、他の回答・採点と生成識別値を保持すること、この実行の要求数が再利用分を含まないこと、読み取り専用runの起動拒否、条件不一致の拒否を検証している。ベンチマークの品質結果を用いて再利用条件を緩めない。
