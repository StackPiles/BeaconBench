# 03 問題セット・選定・統計

## Quick / Detailedの関係

初版案はQuick 20ケース、Detailed 100ケース。セットは問題ID・分野配分・言語・版を保持する。各ケースの試行回数は独立した実行設定で指定し、両セットとも既定1回。対象は日本語のcase-language単位で数える。試行数とモデルへのAPI呼び出し数は別物で、1ケースが複数対話・操作を含む。

QuickのcaseをDetailedへ含め、条件が一致するcase・trialの回答を再利用する。両者は同じ生成プロトコル・翻訳・データ・ハーネス・採点器を参照する。全条件のfingerprintが一致したときだけ回答を再利用できる。問題数や予定試行回数の違いだけで生成の同一性を無効化しない。Quickを3回、Detailedを1回測る場合は共通caseのtrial 0を再利用し、他の原本も保全する。

独自の累積出力・操作回数制限は両方でnull。Quickの短時間化は、ケース数と、実測時間の短いケースを含む選定によって行う。品質を見て都合のよい問題を選ばない。所要時間は指定回数と予備測定を使った推定分布として示し、固定時間での完了を保証しない。

[Quick案](../suites/quick.v0.draft.json) と [Detailed案](../suites/detailed.v0.draft.json) に配分を記録した。全case_refsは空で、いずれも実行不可。問題IDの採用と日本語QAを終えて別のfrozen manifestを発行する。

## 選定の単位と基準

| 軸 | 方針 |
|---|---|
| 分野 | 各候補の固有能力を重ね過ぎず含める。コード・数値だけに偏らせない |
| 難易度 | 上流の難易度・構造情報を優先。独自難易度は根拠を保存 |
| 入力長 | 短・中・長を含め、要求と資料を読む能力も確認 |
| 行動 | 単発回答、複数ツール、顧客対話、状態変更、修正を分ける |
| 営業 | 商品・顧客の抵抗・難易度・購入適合性を広げる |
| 独立性 | 同じ主問題・派生問題・原文翻訳ペアをcluster化 |
| 実行性 | 参照解が動き、仕様に従う正答と誤答を採点器が識別できる |
| 時間 | 正誤を見る前に予算なしの予備測定で把握し、長さを選定理由として記録 |

選定理由、候補母集団、選定seed、層、代替候補を保存する。単純な先頭N件や、特定モデルが通った問題だけの選定をしない。調整に使ったケースは開発用として記録し、採用判断用の未使用ケースを確保する。

SciCodeは独立小問と累積主問題を別trackにする。独立小問で前提コードを渡す場合は、渡すコード・背景条件・参照実装由来の情報まで固定する。独立小問の正答率を主問題の完遂率へ読み替えない。

## 得点

- 単発コード：そのcaseの固定した全テストが通るか。テスト数と通過数も保存。
- 科学：独立小問 / 累積主問題の各単位、背景条件、2環境ORの判定を保存。
- 最適化：公式の連続点、実行可能性、各入力の原目的値、平均の重み。
- 業務・対話：上流が定義したタスク成功、部分点、最終状態、規則違反。
- 営業：過程と会話末尾の購買意向を保存。日本語の較正済み規則による派生点を別名で表示。

単位・意味が異なる得点を無条件に平均しない。分野別の品質と、同じケースでのトークン・時間を主な比較表とする。集約点を作る場合は、変換・重み・対象分母をモデル結果を見る前に別版で定義する。

## 反復と統計

独立した[実行設定](../execution/default.v0.draft.json)は `trials_per_case`（既定1）、`seed_policy`、全試行集計の方針を持つ。同じ比較内の全モデル・生成presetへ同じ回数とseed方針を適用する。0・負数・小数・未入力は拒否し、黙って1へ置換しない。1 / 3 / 5回は入力補助で、上限ではない。

seed方針案は `sha256-case-revision-trial-v1`、基底seedの既定は42、trial indexは0から。導出入力はUTF-8のJSON配列 `["beaconbench-seed-v1", base_seed, case_id, case_revision, trial_index]`（余白なし・非ASCIIをescapeしない）。SHA-256の先頭4 byteをbig-endian整数として読み、`0x7fffffff`とのbit ANDでnative seedを得る。case版は固定した生成入力・環境の版を指す。実装受入ではUI / CLI / adapterの既知vectorを照合する。

モデルID・suite ID・予定試行回数をseedの導出へ含めない。回数追加でも既存trialのseedは変わらず、新しいrun planから不足分だけを追加できる。過去runを書き換えない。seedが同じでも、異なるtokenizerやGPU実装で同じ文章になる保証はない。seedを受け付けないモデルは `seed_effective=unknown` と記録し、対応試行の意味を明示する。

既定の品質は全試行を使い、caseごとの成功回数 / 採点対象回数を固定case集合で集計する。予定・完了・採点済みの分母も表示する。最良回答だけを選ぶbest-of-Nへ置換しない。1回から反復分散を0と推測しない。

通常の試行成功率と「全N回で成功するcase率」は別metricで、後者を比較するときはNを揃える。N=3の場合、BabelArenaのPass^3は「3回すべて成功」であり、pass@3の「3回中1回以上成功」と取り違えない。

信頼区間はcase / 元主問題のclusterを単位に、分野の層を保ったbootstrapを基本候補とする。同じ問題のN反復や日英ペアを独立した新問題として水増ししない。単純な二項区間は独立性が妥当な単一試行の二値部分集計に限る。ペア差は同じcase・trialを対応させ、品質差と完了時間比を示す。異なる回数のrunでは共通trialの比較と全結果の集計を区別する。

100ケースや同じ問題の反復だけで数ポイント差を確定できるとは限らない。区間は選定済みセット内の変動を表し、手選別した問題から全公式ベンチマーク・全業務へ一般化する根拠にはしない。

## 分母・異常・時間

planned、attempted、completed、scored、model failure、infrastructure error、invalid simulator、unsupported、interruptedを別々に数える。公式ルールのtimeoutが0点になる場合はその点と理由を残す。対象外・未実装・未実行を誤答へ換算しない。

時間は全試行の分布と、両構成が共通して正答・完了したcaseのペア比較を併記する。早い誤答が全体の品質を隠さないよう、品質と時間を並べる。中断・timeoutの時間は打切りとして残し、成功例の平均へ混ぜない。

## 日本語と英語の対照

主な20 / 100の分母は日本語。翻訳の対照は別のQAセットとする。case IDで対応させ、日本語にしたことによる入力長・品質・時間の変化を見る。顧客役や採点器も変わる場合は、その差を言語だけの効果と呼ばない。
