# 06 日本語化と測定器の検証

## 主評価と原本

選定した日本語ケースを初版から用意する。BabelArena等の公開済み日本語を優先し、原本との対応と出典を保つ。独自翻訳は `BeaconBench Japanese adaptation` と表示し、上流公式日本語と同一視しない。

原文はimmutable。翻訳の修正、日本語の補助モデル変更、採点基準の変更はそれぞれ別の版とSHAを持つ。検証前の翻訳を本評価用manifestへ入れない。

## 翻訳対象

| 項目 | 扱い |
|---|---|
| 問題文・背景・依頼・system指示 | 意味、必須条件、否定、例外を保って翻訳 |
| 顧客persona・商品説明・社内規則 | 非公開情報の境界、買う条件、値引き権限等も同じにする |
| tool説明・DB内の人が読む文章 | entity mapを用い参照を一貫させる |
| 数値・単位・通貨・日付・数式 | 原則そのまま。意味を変える換算や日本市場への置換をしない |
| tool名・引数名・ID・列名・enum | 実行契約として維持。日本語の説明を別に持つ |
| コード・テスト・参照解・固定文字列出力 | 実行意味を保つ。言語依存の出力を翻訳する必要があれば採点資産も別版 |
| 採点prompt・正解rubric | 日本語回答を評価できるように対応。変更と較正結果を保存 |

翻訳で不足仕様の補完、解法のヒント、商習慣・価格・商品そのものの変更をしない。不備を見つけた場合は翻訳作業と分けてissue化し、全モデルに共通の修正版か対象外の扱いを先に決める。

## Language pack

case ID、元source revision、原文SHA、翻訳SHA、翻訳対象JSON pointerのallowlist、用語集、entity対応、translatorのIDと版、reviewerのIDと版、検証結果を持つ。translator・reviewerと評価対象を区別する。

予定状態は `draft → translated → reviewed → controls_passed → instrument_calibrated → frozen`。コード課題のように補助モデルを使わない場合は、instrument較正がnot_applicableである理由を残す。

## 内容と採点の確認

1. **保護項目の自動照合**：数値・単位・ID・コード・制約式・参照関係の意図しない変更を検出する。
2. **独立した原文照合**：翻訳とは別のreviewerが、制約・否定・例外・曖昧さを全文確認する。逆翻訳は補助材料にする。
3. **採点control**：参照解、明確な不正解、境界の許容誤差、未完了・形式違反を固定し、判定と証拠を保存する。
4. **少数の日英対照**：複数の能力のモデルまたは参照回答で、翻訳による不成立や採点の偏りを探す。得点の完全一致は要求しない。
5. **版の固定**：回答を見て翻訳を都合よく変えない。変更時は新しいpackにする。

自動reviewの二者一致を、人間が確認した正解率と呼ばない。人手の確認を行った範囲と、自動だけの範囲を表示する。

## SalesLLM日本語派生版

[CustomerLM](https://huggingface.co/MultiSense/CustomerLM) と [SaleIntent-BERT](https://huggingface.co/MultiSense/SaleIntent_bert) は英語・中国語の評価を公開している。日本語が生成できることと、顧客役や購買意向判定が妥当であることを分けて検証する。

### 顧客役

- 担当するpersona、商品知識、予算、拒否理由、購入条件を守る。
- 営業側に回って売り込みを手伝わない。
- 買わない条件では安易に同意しない。明確に条件を満たす場合には適切に反応する。
- 営業対象モデルに合わせて顧客役や設定を変更しない。

候補はCustomerLMの日本語での忠実さの検証、または日本語に対応する別の固定顧客モデル。変更した場合は別の測定器であることを明示し、英語の元スコアと同じ系列にしない。

### 採点役

日本語の購買意向判定には、成約意思あり・保留・不適合・丁寧な拒否・不満等の固定会話例を用意する。顧客の発言を根拠に判定し、営業文が流暢という理由だけで高得点をつけない。商品事実や権限を破った成約も監査する。

日本語LLM judgeや日本語分類器を候補にし、人が確認した少数の較正集合でクラス別の誤判定・不明・一致率を確認する。較正閾値は本評価前に決める。日本語会話を英語へ戻して原版BERTで採点する方法は補助診断の候補であり、翻訳による購買意向の変化を含むので無検証の主採点にはしない。

較正に失敗した場合はSalesLLM日本語をreadyにしない。別タスクを黙って入れてセットを完成扱いにしない。

## 対話中の異常と評価

顧客役の役割崩れ、変換器の内容欠落、採点器の出力不正は原本とともに記録し、対象モデルの不正解とは別の `invalid_instrument` とする。その検出規則をモデル結果を見る前に固定する。都合の悪い会話だけを除外せず、対象件数と総消費も報告する。

モデル間比較は同じ日本語pack・同じ顧客役・同じ採点器で行う。日英差を示す場合、測定器変更の有無も明示する。品質・トークン・時間は言語別に集計する。
