# Vita crossの支払い完了と顧客の終了

2026-10-29。配送注文の支払いを依頼した発言に終了記号が付くと、エージェントが支払いを実行する前に対話が終わる。crossだけに `vita-delivery-payment-completion-v1` を明示し、顧客の確認文と終了制御を別の生成条件として受入する。公式の主採点や他の課題の条件は変えない。

## 実ツールの結果を用いる

固定版の[配送ツール実装](https://github.com/QwenLM/BabelArena/blob/36960fbb7ee1aac5082fa7307264abc612a180f4/benchmarks/vitabench/src/vita/domains/delivery/tools.py)では、配送注文の作成時は未払いになる。支払い操作が成功すると状態がpaidになり、成功結果を返す。状態照会からも確認できる。

制御は、この対話で作成された配送注文だけを追跡する。支払いツールの成功結果か、注文IDに対応する状態照会の結果を根拠とし、エージェントの「支払い済み」という説明、別注文の支払い、商品名や注文備考の文字列を確認根拠にしない。対象エージェントの入力と出力には変更を加えない。

顧客役には、固定要望を保持する従来の確認文に加え、支払いの依頼・承認と完了を区別する文、検証済みの現在状態を渡す。未払いが残るときの終了記号は除去して対話を継続する。新しい出力を引き直す処理ではない。原応答はそのまま保存し、転送した内容、両方のSHA、判断理由、ツール結果への参照も記録する。

キャンセルした注文を未払い債務として残さない。実ツールが支払い失敗を返した場合は、それを支払済みにせず保持する。元の技術的失敗による終了規則に従うときは、顧客が「支払いは未完了です」と明示した終了を別に記録する。支払い未完了の失敗を正常な支払完了と呼ばない。

## 版と受入

`generation.policy.vita_payment_completion` と、顧客役の受入条件にある制御の版・確認文SHA・実装SHAを照合する。cross以外への誤適用、未受入の差し替えは拒否する。既存の顧客役を黙って書き換えず、新しいセットIDと測定計画を作る。

`fixtures/vita-payment-controls.json` の6つの架空確認問題で、固定した部屋条件、平日には不要な予約、支払い承認後の待機、根拠のない支払完了宣言、実際の支払成功、確認済み技術的失敗を検査する。実モデルの原要求・SSE・原応答・転送内容と判定を保存する。6件すべての受入を確認したが、母集団の顧客忠実度を保証する結果ではない。

終了制御は別途、早すぎる終了、別注文、偽の支払い宣言、備考に含まれるpaid、複数注文、支払い失敗、再生履歴、対象モデルへの非干渉を確認する。固定した公式支払い関数を架空のメモリ内注文に適用し、成功結果と照会の形式も照合した。実際の金銭取引は行わない。

## 保存と再測定

ケースの保存先に `payment-guard.json`、顧客要求ごとに `payment-termination.json` を残す。`native-result.json` の `customer_payment_guard` にも、注文状態・参照したツール結果・終了を待たせた回数を記録する。原回答・原採点・原対話は上書きしない。

[部分再測定](19-subset-remeasurement.md)では、直前に完了した統合結果を再利用元にできる。crossだけを新しく測り、他の19件は最新の回答と採点を保持する。複数の統合を経ても、元の採点原本とその根拠への参照を保持する。計測用runの1件の生成・採点・統合が終わったら有限の管理処理も終了し、他の試験へ続けない。
