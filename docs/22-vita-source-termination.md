# Vitaの公式終了条件と全文による根拠検証

v1の仕様を以下に保持する。公式の商品意味、宿泊などを含む予算、保存回答の別版点検と停止理由の表示は[終了検査v2](23-vita-source-semantics.md)を参照。旧runへv2の判定を上書きしない。

2026-10-30。顧客役の早い終了と、追加した補助検査の誤検出を別の測定器の問題として扱う。対象モデルの注文漏れ、元の公式得点、生回答、生判定を保持する。今回の実装指示は修正と検証であり、本評価の再測定を自動開始する指示ではない。

## 基準と変更範囲

基準は固定版の[公式顧客指示](https://github.com/QwenLM/BabelArena/blob/36960fbb7ee1aac5082fa7307264abc612a180f4/benchmarks/vitabench/src/vita/prompts/user_system_prompt.yaml)と[終了処理](https://github.com/QwenLM/BabelArena/blob/36960fbb7ee1aac5082fa7307264abc612a180f4/benchmarks/vitabench/src/vita/user/user_simulator.py)。顧客は要望を段階的に伝え、固定条件を放棄せず、未完了の操作がある間は終了しない。全要望を伝えた後にシステムが技術的に完了不能と明示した終了は認める。

元の問題、採点基準、要求する作業、対象モデルの生成設定を変更しない。任意の希望や成立しない分岐を必須にせず、情報提供だけの依頼へ注文・支払いを追加しない。顧客への確認文と追加検証は公式コードそのままの実行ではないため、別版として明示する。

## 終了の検証

`vita-source-termination-v1`を生成方針へ明示し、顧客役と`termination_judge`の受入を必須にする。顧客には元規則の終了前確認だけを加える。正解、採点項目、必要なツール列、過去の対象モデルの失敗を渡さない。

顧客が公式の終了記号を出したとき、別の検証呼出しで実際の固定指示・会話全文・ツール結果を確認する。対象モデルの履歴と顧客側の役割を混同しない。全条件を点検表に含め、開示・実完了・未達・不明・適用外を区別し、原文と一致する根拠引用を検証する。技術的完了不能の例外には、全要望を事前に伝えた根拠と対象エージェントの明示的な表明が必要。

終了可能という候補は、同じ全文を与えた別の検証でも裏づけを確認する。完了宣言だけを操作完了の証拠にせず、一部の手配が済んだことを全体の完了へ拡張しない。検証はLLMを含む測定器であり、論理的に完全な正しさを保証するものではない。独立した正負controlと保存対話の回帰確認を受入条件とする。

許可した顧客発言は終了記号を含めてそのまま転送する。不適切・不明な終了は`InvalidCustomerTermination`として原応答と判断を保存し、測定器の失敗として停止する。終了記号を除いて対話を延長したり、不足項目を対象モデルへ通知したり、顧客の発言を引き直したりしない。失敗による正当な終了を成功と表示しない。

同じ試行を通常の再開操作で再生成することも拒否する。測定器を修正・受入した別版での計測は、別の明示的な実行指示が必要。対象モデルの失敗を取り消すための再試行には使わない。

旧支払い確認の終了記号書換えとは併用できない。従来の`vita-delivery-payment-completion-v1`と固定条件v1のコード・方針は保持し、既存の凍結runtimeや過去のrunへ遡及適用しない。

新しい顧客条件では、完了後の即時終了まで求める固定条件v1の確認文も併用しない。公式指示と固定条件保持の基本確認、今回の終了前確認だけを使う。公式は終了可能な条件を定めており、その条件を満たした直後の終了を義務にしない。確認を続けたことだけで顧客を不合格にしない。

## 補助検査v2

`vita-source-evidence-v2`は、顧客の固定条件保持を項目ごとに点検する。終了の適否と対象モデルの成否は別に扱う。

従来の顧客発言だけの反例探索をやめ、一次判定と根拠検証の両方へ、提案・注文内容・ツール結果を含む同じ全文を渡す。元条件にある金額・数量・種類の対象範囲を確認し、合計予算と内訳、ランク内の同一商品と全ランク共通の商品を区別する。適合する提案の了承を違反にせず、仮定や推測だけで条件の放棄を認定しない。

検査役は1項目の判定と引用だけを返す。全体の`consistent / violation / unknown`は、その項目結果からプログラムで集約する。条件放棄と判定しながら全体は整合とする矛盾した形式を作らない。

引用文の転記による数値・表記・発言番号のずれを防ぐため、モデルは根拠の発言番号を選び、プログラムが保存原本の本文をそのまま引用へ変換する。存在しない番号や本文のない参照は拒否する。明示的に引用文が返された場合も完全一致を要求し、曖昧な照合や引用の修復は行わない。指示の引用元も点検対象の元条件へ固定する。

発言番号は`{"message_index": 2}`と整数`2`の両形式を同じ参照へ正規化できる。真偽値、小数、範囲外の番号は受理しない。形式の正規化だけであり、根拠の追加・推測や判定ラベルの修正には使わない。

引用の存在だけでは意味の正しさは確定しない。別の全文検証で候補の意味も確認し、裏づけられない候補は不明として残す。原応答、一次候補、検証結果、最終判定を別々に保存し、公式得点へ独自の加減点を混ぜない。

## 比較と受入

顧客・測定器の不具合と対象モデルの失敗を混同しない。比較からの留保は固定規則に基づいて全モデルへ同じように適用し、得点が低いという理由で除外しない。失敗・留保・欠測の件数と元の得点を表示する。

`fixtures/vita-source-controls.json`は独自に作成した確認問題。適合する提案の了承、明示的な放棄、合計と内訳、訂正表現、対象モデルだけの誤り、任意条件、分岐、未注文、数量違い、技術的失敗、情報提供だけの依頼を含む。固定条件v1の独立controlも回帰確認に使う。保存済み実対話は別枠の回帰確認であり、未使用の評価集合とは扱わない。

実モデル検証の受入は、生の要求・応答、モデル・生成設定・確認文・実装SHAへ結び付ける。失敗した確認も保持し、同じ条件の出力を引き直して合格にしない。固定した独立controlの一致は開発用受入であり、母集団の判定精度ではない。

生成・モデルによる検証は計算先、管理・保存・表示は中継先。終了検証の消費量は`termination_judge`へ分けて計上する。新しい補助役は別版のセットを受入するまで既存の本評価へ自動適用しない。

終了検証の待ち時間が対話末尾に加わるため、旧版と新版の課題時間をモデルの速度差として直接比較しない。対象モデルの要求時間・出力速度と、検証役の要求時間を分けて参照する。元のnative時間を独自の推定値で書き換えない。
