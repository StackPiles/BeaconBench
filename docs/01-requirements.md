# 01 要件と比較対象

## 目的

ローカルLLMを新規導入・更新・量子化・エンジン変更するとき、業務や開発に必要な作業品質がどう変わり、どの程度のトークンと実時間を使うかを、再現可能な同じ手順で比較する。

対象は計画、知識・ツール操作、複数工程の業務、実装、科学計算、最適化、営業対話・営業実務。単発回答だけでなく、模擬環境での行動と最終状態を確認する。

この評価は実際の業務へ組み込むモデル構成の選定材料となる。長期間の組織運営、実際の売上・収入、現実の顧客との契約成立までを証明するものではない。

## 合意した要件

| ID | 要件 |
|---|---|
| R01 | 公開された共通リポジトリで通常能力を比較する |
| R02 | 小規模のQuickと、広い範囲・反復を持つDetailedを用意する |
| R03 | 独自の累積出力トークン・操作回数・対話回数制限を設けない |
| R04 | 品質に加えてトークン消費・速度・課題完了時間を測る |
| R05 | 営業の能力も候補に含める |
| R06 | 選定問題の日本語版を初版から準備し、日本語を主評価にする |
| R07 | 公開済み日本語を優先し、独自翻訳は原文・検証・版を対応づける |
| R08 | 可能な範囲で上流の採点器を利用し、独自変更を明示する |
| R09 | 原回答・操作・判定を保存し、再開と再採点を可能にする |
| R10 | 中継ホストは中継・保存・監視を担い、重い推論・採点を割り当てない |
| R11 | 過去の14問と共通採点v2の互換条件を保存し、新しい日本語評価と区別する |
| R12 | モデル・設定を登録して画面で容易に選択・複製・比較できる |
| R13 | 進捗・品質・消費・速度・回答・根拠を、見やすい画面で確認できる |
| R14 | 非公開のプロジェクト名や個別業務を識別する情報を公開しない |

20 / 100ケース、Detailedの3反復、具体的な配分は初版案。翻訳対照の件数、補助モデル、日本語採点器、問題IDは未固定。

## 比較単位

一つの構成は `モデル重みとrevision × 量子化 × 推論エンジンとビルド × 実行ハードウェア × 思考設定 × 実行プロトコル` で識別する。MTPやその他の推測実行、KV形式、GPUグラフ、キャッシュ、並列度も構成に含む。

同じモデル名であっても重みや思考設定が異なれば別構成。モデル単体の差とエンジン変更の差を調べる比較では、変更する要素を絞る。各モデルの実用構成全体を比べる場合は、その条件を表に残す。

同一文章でもtokenizerが違えばトークン列と消費量は変わる。異なるモデルへ同じトークンIDを強制しない。同一モデルのエンジン違いでは、対応可能ならレンダリング結果と入力IDの一致を確認する。

## 制限を追加しない範囲

独自の累積出力・操作・対話回数・課題時間の上限はnullとする。Quickも同じ。問題数と反復数の小ささが主な軽量化になる。

次の終了条件は別に記録する。

- 公式タスクの交渉期限、ゲーム期間、コード実行時間、ベンチマーク固有の壁時計期限。
- モデル・エンジンのコンテキストと一要求の出力可能量。
- 接続切断、プロセス異常、利用者の停止、計算ホスト停止。

公式の期限を外すと問題自体が変わる場合は元のルールを保つ。途中終了した記録は保全し、完了回答と取り違えない。独自上限を後から導入する場合は、新しいプロトコル版とする。

## 初版の範囲

1. 日本語の固定課題セットと実行条件・採点規則の管理。
2. OpenAI互換APIに接続するモデル側アダプター。
3. 単発コード評価と、模擬ユーザー・ツールを含む対話評価。
4. 品質・消費・時間の比較と、回答・証拠まで辿れるローカルレポート。
5. 個別環境から独立した設定テンプレートと、公開資産の取得・検証手順。
6. 名前付きモデル・設定プリセットと、比較を組む画面・進捗画面・結果比較画面。

モデルの重み改変、推論カーネル開発、常用サービスの再構成、自動スケジュール、実顧客への営業活動はこの初版の実装対象に含めない。
