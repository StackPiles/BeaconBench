## 明示した修正と元の規則

- Clawのfixtureを固定日付で実行する。追客はtaskとrubricが示す2026-03-26、メール返信はfixture直後の2026-03-01、会議は元の2026-03-03。元YAMLも保持する。
- VitaのJAユーザー説明は終了条件を示すが、実装が要求する `###STOP###` を指示していなかった。既存条件を満たす場合だけマーカーを付ける補足を別版として追加した。終了条件・回数制限は追加していない。
- SDKの隠れた再送を無効にし、長い推論を独自の応答待ち時間で切らない。nativeのJSON変換再試行など、元の意味的な処理規則は記録して保持する。
- Clawが要求するストリーム形式にも対応する。native SDKには蓄積した内容をストリーム形式で返すが、速度・TTFT・usageの原本は推論接続先のSSEに限る。
- LCB `abc392_d` は、元AtCoder規則の絶対または相対誤差1e-8を版付き採点方針として固定した。他3問の比較方法は変えていない。
- 提出したFrontierプログラムのコンパイル失敗はnativeの0点と区別情報を保存する。checkerや環境側の失敗を0点へ落とさない。

フレームワーク独自の累積出力・操作・対話・締切上限はない。元の規則は残る。τは200 steps、Vitaは100 steps、Clawは各taskの25/20/30 turnsと300/300/600秒、購買は元の各loop上限・20分・反復停止、旅行は150 calls、CRMは20 turns、営業は生成した話者メッセージ20件である。ベンチマーク固有の終了条件と、モデル1要求あたりの出力上限を区別する。

## 実行方法

受入済みのインストールでは、画面で「Quick20 · 日本語 v1」、対象モデル、生成設定、各ケースの試行回数を選び、実行計画を確認する。既定は1回で20試行。試行回数を変えても問題セットは変わらない。

別環境では元の利用条件に従って資産を取得し、独立したnative環境、固定image/source/data、モデルと較正証拠を用意する。`tools/native/babel_task.py` はprivateなdata/tokenizers/overlaysと同じ作業rootへ設置する一件実行用wrapper。

```sh
uv run beaconbench suite-import local/quick20-ja-v1.json
uv run beaconbench plan local/quick20-plan-request.json
```

公開manifestだけで未準備の環境をreadyへ変えない。実行計画の作成はモデルを呼ばず、本測定は画面またはCLIで明示的に開始する。元の実測・回答・温度別結果・確認で失敗した記録も保持する。
