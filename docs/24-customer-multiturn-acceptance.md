# 模擬顧客の複数ターン受入比較

2026-10-31。顧客役の受入試験を複数ターンへ広げ、元版と自前候補を同じ条件で比較する明示指示に基づく。通常の能力ベンチマークと、測定器である顧客役の品質確認を分ける。

## 問題と比較条件

[独自作成の12シナリオ](../fixtures/customer-multiturn-controls.json)を、両版の生成前に固定する。必須条件間の妥協への誘導、個数・合計予算、別枠予算、既知・未知の情報、許可された代替、任意の希望、成立しない分岐、提案と実行の区別、技術的完了不能を含む。通常の相談をするpersonaと、費用を論理的に比較するpersonaを含める。

各シナリオの相手役は事前に決めた4または6発言。各版で最大60回の顧客応答を測る。これは受入問題の範囲であり、通常ベンチマークへ対話回数や累積出力の制限を追加するものではない。試行は各ケース既定1回で、合格までの引き直しをしない。

相手役の発言列、顧客の初期指示・persona、case/turnから派生したseedを両版で同じにする。2回目以降は各モデル自身が実際に生成した返答を履歴へ戻すため、その部分の入力は自然に分かれる。相手のモデルの返答や、事後に修正した返答へ差し替えない。

履歴は固定したVitaのrole反転に合わせ、顧客の本文とtool_callsをassistant役へ戻す。生成された思考は原本に保存するが、元のnative形式にない過去の思考を新しく履歴へ注入しない。公式日本語templateと、現在使っている基本確認文・終了前確認文を固定する。受入基準や採点上の期待結果は顧客へ渡さない。

生成設定は現在の顧客役と同じ温度0、top-p 1、top-k無効、思考ありxhigh、256Kコンテキスト、各要求の思考込み出力16K。対象モデルの通常評価で使う温度1・出力128Kとは目的が違う。エンジン、量子化、KV、MTP、グラフ設定は両版で揃え、重み介入の有無だけを変える。実機の条件は公開リポジトリへ含めず個別の固定記録へ保存する。

## 終了と判定

顧客がSTOP等を出した場合、その応答を原本どおり保存してそのシナリオを終了する。終了記号を消したり、続きを生成させたりしない。未完了の時点での終了はプログラムでも検出する。終了が許される時点でも、必ず終了記号を出すことまでは要求しない。相手役がSTOPを出す台本は、公式ならそこで対象側の測定が終わるため使用しない。

判断は条件別のfaithful / violation / unknown。顧客の実際の発言を根拠にし、相手役の誤りだけで顧客を違反扱いにしない。引用による訂正、明示的に許された代替、任意条件や不成立の分岐を不適合な妥協と区別する。未完了・上限到達・判定不能を合格や0点へ置き換えない。

採点には両版で同じ固定した元版の判定器を使う。顧客のモデル名・設定・時間・思考を判定入力から除き、全文の一次判定と独立した確認を保存する。根拠の番号から原文をプログラムで取得し、顧客違反には顧客自身の引用を必須にする。不一致はunknownとし、別の判定を引いて確定させない。

判定器には別に独自作成の正負8controlを固定し、比較対象の応答より先に基準を確定する。全controlを正しく判定できない場合は自動の受入結論を保留し、比較対象の生成原本を保存して停止する。判定器のcontrolは顧客役の12問題とは別に管理する。

固定された少数の開発用受入問題であり、母集団精度や他モデルへの優越性を保証しない。元版の判定器による自己評価の偏りもあり得る。一次・確認が同一モデルで一致することだけを独立した正解保証と扱わず、最後に原文と根拠を点検できる成果物を残す。

## 記録と運用

両版の生成・判定は計算ホスト、管理・原本保存・監視は中継ホストで行う。中継ホストでモデルや採点器をロードしない。管理処理は表示用Windowsから独立させる。既存のSSH制限を維持し、固定SHAを検査する比較専用コマンドだけで計算ホストへ接続する。

相手台本、初期指示、基準、判定器のcontrol、コード、重み・介入の記録を初回推論前に固定する。比較時だけ一時的なエンジンを使い、既存サービスのアイドルを確認してから占有する。終了・失敗時に元の同じ常用環境へ戻す。画像モデルと過去の回答・得点・判定は保持する。顧客役の自動採用、通常ベンチマークの自動再開は行わない。

応答本文、思考、SSE、実要求、usage、API完了状態、引用根拠、一次・確認の原判定を保存する。条件保持の件数とunknownに加え、思考込みの生成トークン、思考トークン、要求時間、入力処理を含む生成スループットを比較する。欠測のusageを0で埋めず、初回ロードと生成・判定の時間を区別する。

## 検証用CLI

```sh
uv run beaconbench customer-controls-validate fixtures/customer-multiturn-controls.json
```

このコマンドは問題の形式・引用元を検査するだけで、モデルへ接続しない。実モデルの比較実行と稼働設定は明示的に準備・起動する個別の管理処理に任せる。
