# Vitaの固定条件保持と項目別点検

2026-10-29。顧客役が、元の部屋種類の指定に反する構成を了承し、従来の整合性検査も見落とした。顧客条件の保持と事後検査を `vita-fixed-goals-v1` として別版にする。公式得点は変更せず、測定条件の忠実さを独立して記録する。

## 顧客役へ渡すもの

顧客が実際に受け取った元の `<instructions>` だけから、文単位の一覧を機械的に作る。人物設定、公式採点の正解、満たすべきツール列、対象モデルの過去の回答を追加しない。元の数値・種類・日時・条件分岐は書き換えない。

顧客役は各ターンで一覧と直近の提案・操作結果を照合する。予算が合っていても種類や数量の相違を了承せず、元条件を伝えて訂正を求める。元の指示が認めた選択や柔軟性、段階的な情報開示、技術的に完了不能な場合の終了規則は保つ。[支払い完了の確認](20-vita-payment-termination.md)も維持する。

「予定」「希望」などの語尾だけを代替許可とは扱わない。在庫不足や合理性を根拠に、指示にない優先順位を補ったり、指定された種類を「その種類を中心に」と読み替えたりしない。代替が元の指示で明示されている場合は、その許可を保持する。これは[元のユーザー規則](18-evaluation-contracts.md)の要望を変更・置換・一般化しない原則に合わせたもの。

対象エージェントのシステム指示、生成条件、回答を直接変更しない。顧客の返答を引き直したり、事後に正しい返答へ置き換える処理は追加しない。顧客への確認文は元の規則の補強だが測定器への変更なので、元条件と同一版とは扱わない。

## 項目別の事後検査

検査役へ、実際の顧客指示と保存対話の全文を渡し、原文の1項目ずつを別の呼び出しで点検する。末尾の対話も原文のまま再掲し、前半で正しい条件を伝えたことが後半の放棄を隠さないようにする。対話を切り捨てたり、要約で置き換えたりしない。

各項目について、保持、変更・放棄、不明、適用外・背景の判断と根拠を保存する。保持と放棄には実際の発言からの引用を必須とする。放棄の判定は、元条件からの引用と顧客自身の発言からの引用が対応する場合だけ受理する。点検結果は機械的に集約し、単一の全体的な印象による整合判定は使わない。

保持と判定した項目は、元条件と引用・直近の顧客発言だけを別に照合する。一次判定の結論・理由は渡さず、条件変更を直接示す反例を探す。検証できる反例があれば放棄として集約する。反例が見つからない場合は一次判定を維持し、これだけで対話全体の整合性を保証したとは扱わない。引用や返却形式が不正な場合は不明として比較を保留する。

一次判定、引用照合の原応答、引用検証後の集約結果を別々に保存する。元の判定を後から書き換えない。

対象エージェントが条件を満たさなくても、顧客が訂正を求めていたら顧客の放棄にはしない。提案の引用、疑問形の訂正、許可された選択も放棄とは区別する。

項目の欠落・重複、架空の引用、全体判定との不一致、入力不足がある場合は比較を保留する。条件違反があれば全体はviolation、違反がなくても不明項目があればunknownとし、consistentを推測で補わない。公式得点はそのまま保存し、画面の採点根拠に条件ごとの点検と引用を表示する。

## 受入と再測定

`fixtures/vita-goal-controls.json` に独自の架空確認問題を固定した。顧客役9件と検査役11件で、複数制約の独立保持、許可された柔軟性、完了待ちと条件保持の区別、予定という語尾と代替許可の区別を確認する。従来の支払い確認6件も新しい顧客条件で確認する。旧回答は、全文を入力して既知の問題条件を点検する回帰確認として別保存し、独立controlの代用にはしない。回帰確認の条件範囲と本評価で全項目を照合することを区別する。実モデルの確認が合格したことは、個別の受入記録で証明する。

確認文・処理コード・検査文・モデル・生成設定と較正証拠を固定する。条件ごとの全呼び出しの原要求・生応答・検証結果も較正証拠のSHAへ含める。顧客の入力・生成条件が同じ場合は保存応答を再利用し、新しい検査で点検した受入記録を別保存できる。従来の条件を使うケースは従来の検査を維持する。

今回の適用は明示したcross1件に限り、新セットで1回再測定する。他の19件は回答・採点・生成識別値を保持して再利用する。元の回答・採点・整合性判定は上書きしない。項目ごとに全文を照合するため検査の呼び出し数と時間は増える。検査役の消費・時間は対象モデルの生成と分けて記録する。

再測定で顧客条件の逸脱が再発しても、成功するまで自動で引き直さない。結果と逸脱を保存して停止し、能力の失敗と測定器の問題を分けて確認する。生成・モデルによる検査・公式採点は計算先、管理・保存・表示は中継先で実行する。
